## Current Blockers
- S01+S02 precisam rodar local (go mod tidy → go build → migrate up → go test -race com DATABASE_URL setado) para validar runtime. Go/Docker/migrate nao estao instalados no workspace do Conductor; execucao pertence ao usuario.
- Backend ainda nao expoe `/tasks/*` (S04+) nem endpoints de leads/pipes/workflows (S07+). Frontend do cockpit segue consumindo fixtures mock ate S06 (integracao front↔back).
- Itens restantes de seguranca `<!-- aguarda S03 -->` no Checklist Sistema Base (CSP nonce-based completo, HSTS com preload no edge, scrubbing de PII no Sentry server-side, audit log de mutations sensiveis, rate limiting) passam para S03.
- `/api/bootstrap` esta exposto mas minimo — feature_flags e WS URL serao populados em S03/S04. `/auth/me` retorna bundle completo (user+org+permissions+csrf_token) conforme Checklist.

## Lessons Learned
- Documentacao do vault pode ficar significativamente desatualizada vs codigo
- Sempre verificar estado real do codigo antes de confiar em status documentados
- Duas taxonomias paralelas no vault causam confusao — cada numero deve ter UMA pasta
- Mudanca transversal que afeta AppShell/roteamento/preferencia de usuario e Sistema Base, nao feature vertical — o numero F17 e preservado apenas como apontador de backlog

## Preferences
- CTO padrao: world-class, dark-first, Go backend, seguranca desde commit 1
- Vault e fonte de verdade para decisoes e specs
- Agentes usados proativamente, com briefings densos e autossuficientes
